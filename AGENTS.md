# Agent Development Guide

Guidance for AI agents working in this repository. Every claim here is verified against the code — keep it that way when you edit this file.

## Project Overview

- **Type**: Single Next.js application (Pages Router). **Not a monorepo** — there are no workspaces, no `apps/`, no `packages/`.
- **Package**: `frontend` (private)
- **Package manager**: pnpm 11.9.0 (pinned via `packageManager` and Volta; `engines.pnpm >= 8`)
- **Runtime**: Node `>= 20` (Volta pins 22.23.1; see `.nvmrc`)
- **Framework**: Next.js 15.2.6 (Pages Router) + React 19
- **Language**: TypeScript 5.7.3 (`strict`)
- **UI**: MUI 6 (Emotion engine) + SCSS Modules
- **Data**: SWR 2 hooks **generated** from an OpenAPI spec by Orval 7 (Axios transport)
- **Validation**: Zod 4
- **Testing**: Vitest 2 + Testing Library + jsdom + MSW 2
- **Tooling**: ESLint (`eslint-config-next`) · Prettier · Stylelint · Husky + lint-staged

This repo is currently a **scaffold**: the API is a placeholder `widgets` domain generated by Orval, and the sample pages are a Bulgarian "Wienerberger" static site. Treat generated code and placeholder content as replaceable.

## Commands

Everything runs against the single app at the repo root — there is no `dev-pro`, `build-pro`, `*-all`, or Turborepo task.

```bash
pnpm dev              # Dev server (http://localhost:3000)
pnpm build            # Production build
pnpm start            # Serve production build

pnpm gen              # Regenerate SWR+Axios client from openapi/spec.yaml (Orval)
pnpm gen:watch        # Regenerate on spec changes

pnpm typecheck        # tsc --noEmit
pnpm lint             # next lint (ESLint + import ordering)
pnpm lint:fix         # ESLint --fix
pnpm format           # Prettier --write .
pnpm format:check     # Prettier --check .
pnpm stylelint        # Lint src/**/*.scss
pnpm stylelint:fix    # Stylelint --fix

pnpm test             # Vitest run (TZ=UTC)
pnpm test:watch       # Vitest watch
pnpm test:coverage    # Vitest + V8 coverage
```

### Verifying a change

1. `pnpm typecheck` (or `lsp_diagnostics` on changed files)
2. `pnpm lint`; `pnpm stylelint` for SCSS
3. `pnpm test` for affected specs
4. `pnpm build` for anything non-trivial

## Environment

- `NEXT_PUBLIC_API_BASE_URL` — base URL for the Axios instance (`src/api/axiosInstance.ts`) and MSW handlers. Copy `.env.local.example` → `.env.local`. `.env.local` is gitignored; never commit secrets.

Path alias: `@/*` → `src/*` (the only alias, from `tsconfig.json`). Prefer `@/…` for internal imports; relative paths are fine for close siblings.

## Code Style

### Imports (enforced by `import/order`)

Groups separated by exactly one blank line, alphabetized within each group:

1. External (`react`, `@mui/*`, `next`, `swr`, `zod`, …)
2. Internal (`@/…`)
3. Parent (`../…`)
4. Sibling (`./…`)
5. Styles (`*.scss`) — always last

```typescript
import Button from '@mui/material/Button';
import { useState } from 'react';
import type { NextPage } from 'next';

import { useGetWidgets } from '@/api/endpoints/widgets/widgets';
import { PageTemplate } from '@/components/layout/PageTemplate';

import { Header } from '../Header';

import type { IProps } from './types';

import styles from './component.module.scss';
```

Rules:

- **Type-only imports must use `import type`** (`@typescript-eslint/consistent-type-imports`).
- No blank line _within_ a group; exactly one _between_ groups.
- **Import MUI via subpaths**: `import Button from '@mui/material/Button'` — not the barrel `import { Button } from '@mui/material'`. This matches all existing code and keeps bundles lean.
- Unused vars are an error unless prefixed with `_`.

### Formatting (Prettier — authoritative)

Single quotes (JSX uses double), semicolons, 120-char line width, 2-space indent, ES5 trailing commas, no parens around single arrow params. Run `pnpm format` rather than hand-formatting.

### TypeScript

- `strict` is on; no implicit `any`. **Never** suppress with `as any`, `@ts-ignore`, or `@ts-expect-error` — fix the type.
- Component props use `I`-prefixed interfaces (`IProps`, `IPageTemplateProps`), inline in the component file or in a co-located `types.ts` for larger components.

### Naming

- Components PascalCase · hooks `useX` · utilities camelCase · interfaces `I`-prefixed PascalCase · constants UPPER_SNAKE_CASE.
- SCSS modules: `componentName.module.scss` (camelCase base name).

### Components

- **Arrow-function components with named exports** — no `React.FC`:
  ```tsx
  export const Component = ({ title }: IProps) => <div className={styles.root}>{title}</div>;
  ```
- **Default export only in `pages/`** (Next.js requirement).
- Folder-per-component (`Header/index.tsx` + `header.module.scss` + `header.spec.tsx`) when there are styles/tests; a flat `Name.tsx` is fine for small pieces.
- Prefer self-documenting code; existing components are comment-free.

## Styling

- **SCSS Modules** for structural styling: `styles.className` from `x.module.scss`.
- **MUI `sx`** for one-off/token-based styling, e.g. `sx={{ mt: 4, color: 'text.primary' }}`.
- SCSS partials live in `src/styles`. `next.config.mjs` adds `src/styles` to Sass `includePaths`, so modules reference them without relative paths:
  ```scss
  @use 'variables' as vars;

  .header {
    background-color: vars.$color-primary;
    @include vars.container;
  }
  ```
- Theme (`src/theme/theme.ts`): light palette, primary `#b30000`, Noto Sans, `borderRadius: 2`. Provided via `ThemeProvider` + `CssBaseline` in `_app.tsx`.
- Stylelint extends `stylelint-config-standard-scss` (see `.stylelintrc.json` for disabled rules).

## Data Fetching (SWR + Orval)

Client data uses **generated** SWR hooks. Do not hand-write API clients or call Axios directly from components.

```tsx
// GENERATED into src/api/endpoints/widgets/widgets.ts by `pnpm gen`
import { useGetWidgets } from '@/api/endpoints/widgets/widgets';

const HomePage: NextPage = () => {
  const { data, error, isLoading } = useGetWidgets();

  if (isLoading) return <CircularProgress aria-label="Loading widgets" />;
  if (error) return <Alert severity="error">Failed to load widgets.</Alert>;
  return (
    <List>
      {data?.map(w => (
        <ListItem key={w.id}>{w.name}</ListItem>
      ))}
    </List>
  );
};
```

- **Never edit `src/api/endpoints/**` or `src/api/model/**`** — they are regenerated and wiped (`clean: true`). Change the OpenAPI spec (or point `orval.config.ts` at the real one) and run `pnpm gen`.
- Transport chain: generated fn → `customInstance` (Orval mutator) → shared `AXIOS_INSTANCE` → returns `response.data`.
- Mutations use generated `swr/mutation` hooks (e.g. `useCreateWidget`).
- Global SWR defaults live in `_app.tsx` (`revalidateOnFocus: false`, `shouldRetryOnError: false`).
- Types come from `@/api/model`.

## Server-Side Rendering

Pages currently fetch **client-side** via SWR; static pages (legal pages) are plain `NextPage` components with no data fetching. When you do need `getServerSideProps`, wrap it with **`withApi`**, which injects `{ baseUrl }` and turns thrown errors into `redirect500`:

```typescript
import { withApi } from '@/helpers/getServerSideProps/withApi';

export const getServerSideProps = withApi<{ data: Widget[] }>(async (context, { baseUrl }) => {
  const data = await fetch(`${baseUrl}/widgets`).then(r => r.json());
  return { props: { data } };
});
```

- Redirect helpers in `@/helpers/redirect`: `redirect500`, `redirect404` (renders `notFound`), `redirect403`.

> **No authentication exists** in this codebase — no Auth0, no `withAuth`, no permissions or API tokens. Don't assume auth is present; add it deliberately if a task requires it.

## Testing

- **Vitest + Testing Library + jsdom** (`vitest.config.mts`).
- `globals: false` → **import test APIs explicitly**: `import { describe, it, expect, vi } from 'vitest'`.
- Specs are co-located: `*.spec.{ts,tsx}` (plus `src/__tests__/` for cross-page tests).
- `vitest.setup.ts` wires jest-dom, RTL `cleanup`, and **MSW**: `server.listen({ onUnhandledRequest: 'error' })`. Every network call a test makes must have a handler in `src/mocks/handlers.ts` (or a per-test override), otherwise the test fails.
- Tests run with `TZ=UTC` (set in both the `test` script and vitest `env`). Keep date logic UTC.

```tsx
import { render, screen } from '@testing-library/react';
import { describe, expect, it } from 'vitest';

import { Component } from '@/components/layout/Component';

describe('Component', () => {
  it('renders the label', () => {
    render(<Component />);
    expect(screen.getByRole('button', { name: 'Save' })).toBeInTheDocument();
  });
});
```

## Forms

A reusable, zod-validated form kit lives in `@/components/form`:

```tsx
import { z } from 'zod';
import { Form, TextBox, Button } from '@/components/form';

const schema = z.object({
  name: z.string().min(1, 'Name is required'),
  email: z.string().email('Enter a valid email'),
});

<Form schema={schema} onSubmit={values => save(values)}>
  <TextBox name="name" label="Name" />
  <TextBox name="email" label="Email" />
  <Button type="submit">Save</Button>
</Form>;
```

- `Form<TSchema>` holds field state via React context; `TextBox` registers itself by `name` and wraps MUI `TextField`; `Button` wraps MUI `Button`.
- `onSubmit` receives `z.infer<typeof schema>` and only fires when validation passes. Field errors appear after blur or a submit attempt.

## Conventions & Gotchas

- **Generated code is off-limits**: never edit `src/api/endpoints/**` or `src/api/model/**` — run `pnpm gen`.
- **No direct Axios in components** — use the generated SWR hooks.
- **No type-error suppression** — fix types properly.
- **Husky pre-commit** runs `lint-staged` (ESLint + Prettier on TS/JS, Stylelint + Prettier on SCSS). Keep changes lint-clean; don't skip hooks.
- **Commits/pushes** only when explicitly requested; no force-push to protected branches.
